# 克隆页面参考

Clone 对话框把日常必填项放在最上方，高级能力默认折叠。普通 Clone 只需要本地目录名和
父目录；其余参数会改变目标 Revision、工作区物化范围或底层读取方式。

![Lore Client 中文克隆页面与高级选项](../../img/lore-client-clone-advanced-zh.png)

_展开“高级选项”后，可以指定历史锚点、选择性同步规则以及更深入的物化策略。_

## 全部参数总览

| 参数 | 默认行为 | 接受的输入 | 实际决定什么 |
| --- | --- | --- | --- |
| **本地目录名** | 使用远端仓库名预填 | 单级目录名 | 新 Instance 在父目录下的文件夹名称；不改变远端仓库名。 |
| **目标父目录** | 未选择 | 现有且可写的本地目录 | 新文件夹创建在哪里；Clone 不会直接把父目录本身变成仓库。 |
| **目标 Revision 或 Branch** | 默认 Branch 的 Latest | Branch 名、完整或唯一短 Revision ID | 新 Instance 首次检出和物化的精确历史锚点。 |
| **选择性同步规则** | 完整工作区 | View 规则文件路径 | 哪些历史路径会写到本地磁盘；不改变远端 Revision。 |
| **使用 Shared Store** | 按设备策略和匹配 Store 决定 | 开/关 | Fragment 保存到专用 Store 还是常规本地存储；不共享工作区状态。 |
| **Bare Clone** | 关闭 | 开/关 | 是否完全跳过工作区文件物化，只取得仓库状态与 Revision 树。 |
| **直接文件 I/O** | 关闭 | 开/关 | 物化文件时是否绕过内存映射；只影响本次 Clone 的文件访问方式。 |
| **Layer 仓库** | 空 | 同一远端上的仓库名称或 ID | Clone 完成时从哪个仓库建立本机覆盖层。 |
| **Layer 元数据键** | 空 | 一个元数据键名 | 如何让主仓库 Revision 与 Layer Revision 按相同元数据值配对。 |
| **依赖根文件** | 空，即不启用依赖选择 | 仓库相对路径，每行或逗号分隔 | 从哪些入口文件开始计算要物化的依赖闭包。 |
| **依赖标签** | 空，即不按标签过滤 | 标签，每行或逗号分隔 | 哪些带标签的依赖边可以参与闭包。 |
| **包含传递依赖** | 关闭 | 开/关 | 只取直接依赖，还是继续向下遍历间接依赖。 |
| **依赖深度上限** | `0` | `0–1024` | 传递遍历最多经过多少层；`0` 代表无限。 |

这些参数分别控制“放在哪里”“检出哪段历史”“物化哪些内容”“怎样存取内容”和“是否叠加
其他仓库”。它们不会改变远端仓库本身，也不会因为填写高级选项而自动 Push。

## 远端仓库摘要

顶部只读显示：

| 字段 | 含义 |
| --- | --- |
| 说明与远端 URL | 当前要克隆的仓库及其完整目标。它是只读值，不会因修改本地目录名而变化。 |
| 默认 Branch | “目标 Revision 或 Branch”留空时，用这个 Branch 的 Latest 作为历史锚点。 |
| 创建者与创建时间 | 远端报告的仓库元数据，仅用于确认目标，不参与本地作者身份解析。 |
| 仓库访问权限 | 远端报告的权限摘要；未报告时显示未知，未知不等于拥有写权限。 |
| Clone 目标 Revision | 远端若已解析则显示精确目标；否则会在 Clone 执行时重新读取 Latest。 |

## 基础参数

### 本地目录名

必填。它是父目录下将要创建的**单级目录名**。不能填写绝对路径、父目录跳转或多级路径。
软件拒绝覆盖非空目录。该字段默认用远端仓库名预填，但只是本地文件夹名称：修改它不会
重命名远端仓库、Repository ID 或默认 Branch。

例如父目录为 `D:\Work`、本地目录名为 `Project-A`，最终目标是
`D:\Work\Project-A`。不要在字段中填写 `D:\Work\Project-A`。

### 目标父目录

必填。单击 **选择** 打开系统目录选择器。Clone 的最终路径是“父目录/本地目录名”。
选择器打开期间按钮显示忙碌状态；权限或平台不支持会在字段旁显示错误。

父目录可以已经存放其他项目，但必须可写。Clone 只创建新的子目录，不扫描或覆盖父目录
中的其他内容。

### 取消与开始克隆

- **取消**：关闭对话框；Clone 进行时禁用。
- **开始克隆**：只有目录名和父目录都有效时可用。

## 高级选项

展开 **高级选项** 后可以配置以下内容。

### 目标 Revision 或 Branch（可选）

接受：

- 完整 Revision ID；
- 唯一的短 Revision ID；
- 远端 Branch 名称。

留空时使用默认 Branch 的 Latest。填写历史 Revision 会得到以该 Revision 为工作区锚点
的 Instance，不会把它冒充为默认 Branch Latest。

- 填 Branch 名时，Clone 在执行时解析该 Branch 的当前 Latest；若远端在此期间推进，
  以执行时读取的真实 Latest 为准。
- 填 Revision ID 时，目标固定，不会跟随 Branch 后续变化。
- 短 ID 必须在目标仓库中唯一；不唯一时必须改用完整 ID。
- 该参数只决定初始锚点，不会创建新 Branch，也不会修改远端 Latest。

### 选择性同步规则（可选）

单击 **选择文件** 选择 View 规则文件；**清除** 恢复完整工作区。View 决定 Clone 时
物化哪些路径，但不删除远端 Revision 中的其他内容。

Bare 模式不物化文件，因此此项禁用。

规则文件是输入模板：Lore 会把规则用于新 Instance 的入站物化。规则中的路径相对仓库
根目录；排除路径意味着“不写到这个工作区”，而不是“从历史删除”。如果规则遗漏任务
所需文件，之后仍可通过修改 View 或同步重新物化。

### 使用 Shared Store

启用后，Lore 按当前远端查找可复用 Store：

- 若设置页已启用自动使用，此选项固定开启，单次 Clone 不能覆盖关闭；
- 若找到健康 Store，界面显示当前容量和文件数；
- 若未配置，Clone 返回明确错误，不会静默改用伪造 Store。

Shared Store 只改变底层 Fragment 放置与复用位置。新 Instance 仍有独立 Branch、View、
暂存和本地更改。关闭该选项也不会删除已经存在的 Store。

## 高级 Clone 模式

### Bare Clone

只克隆仓库状态和 Revision 树，不把文件写入工作区。适合服务、镜像、纯元数据检查或后续
明确物化的工作流。

启用 Bare 后，下列物化相关能力禁用：

- View 文件；
- 直接文件 I/O；
- 初始 Layer；
- 依赖驱动选择性 Clone。

### 直接文件 I/O

绕过内存映射进行文件读写，主要用于兼容性诊断。可能降低大型文件性能。没有明确的文件
系统兼容问题时，建议保持关闭。Bare 时不可用。

它不改变 Revision 内容、Fragment 格式或最终文件集合。典型使用场景是网络盘、特殊文件
系统或安全软件与内存映射不兼容；普通本地磁盘不应为了“更直接”而开启。

## 初始 Layer

用于 Clone 完成时同时配置一个本机 Layer：

| 参数 | 含义 |
| --- | --- |
| **Layer 仓库** | 同一远端上的来源仓库名称或标识。Lore 用它定位 Layer 的独立 Partition；不是本地路径，也不是挂载目录。填写后才启用元数据键。 |
| **Layer 元数据键** | 可选键名，例如 `release`。Lore 读取主仓库目标 Revision 的该键值，再在 Layer 仓库中寻找同值 Revision；它不是要直接填写的版本号。 |

Layer 只属于新 Instance，不进入主仓库历史。若需要团队可复现的固定跨仓库引用，应使用
Link。Bare 时整个区域禁用。

Layer 仓库为空时表示“不创建初始 Layer”。只填写仓库而不填写元数据键时，来源 Revision
由 Lore 的默认 Layer 解析规则决定。元数据键存在但任一仓库缺少匹配值时，Clone 会报告
解析失败，不会随便选择一个 Layer Revision。

## 依赖驱动的选择性 Clone

### 根文件（可选）

每行或逗号分隔一个仓库相对路径。留空表示不启用依赖选择，保持由 View 决定的工作区。

路径从仓库根开始，例如 `Content/Maps/World.umap`，不能使用本机绝对路径。根文件本身
始终进入选择集合；是否加入它们的依赖由后续参数决定。

### 依赖标签（可选）

每行或逗号分隔。只有满足标签的显式依赖边进入闭包。没有根文件时禁用。

标签是依赖边的筛选条件，不是文件标签。空值表示不按标签缩小边集合；填写
`runtime, high-resolution` 时只使用 Lore 中满足所选标签语义的已登记边。它不会扫描
文件名或内容来自动补齐标签。

### 包含传递依赖

关闭时只取根文件的直接依赖；开启后继续沿依赖边遍历。没有根文件时禁用。

“直接依赖”是从根文件出发的一跳边。关闭时仍会包含根文件和一跳依赖，并非只克隆根文件。
开启后才使用深度上限继续遍历二跳及更远依赖。

### 依赖深度上限

范围 `0–1024`：

- `0`：无限深度；
- 正数：最多遍历指定层级。

只有“包含传递依赖”开启时可用。Bare 时禁用。

深度以依赖边跳数计算，不是目录层数。`1` 只覆盖直接依赖，`2` 再覆盖依赖的依赖。
闭包很大或依赖图可能存在长链时，可先使用小深度验证结果；`0` 适合依赖登记完整且确实
需要全部传递内容的场景。

## 参数之间如何共同生效

Clone 先解析目标 Revision，再根据 View 与依赖选择计算要物化的内容，最后按照普通存储
或 Shared Store 写入 Fragment，并可建立初始 Layer：

```text
目标 Branch/Revision
  → 精确 Revision 文件树
  → View 路径范围
  → 依赖根文件与闭包范围
  → Shared Store / 常规存储
  → 工作区物化
  → 可选初始 Layer
```

- View 和依赖选择都存在时，不应理解成“两份内容相加”。它们共同限制本次物化范围；
  预先确认根文件及依赖路径没有被 View 排除。
- Bare 在“工作区物化”之前停止，所以所有只影响文件物化的参数都没有意义并被禁用。
- Direct File I/O 只改变写文件方式，不改变上述集合。

## 参数组合示例

### 普通团队成员

- 目标：留空；
- View：留空；
- Shared Store：按设备策略；
- Bare、直接 I/O、Layer、依赖选择：关闭。

结果是默认 Branch Latest 的完整常规工作区，内容仍可按需获取。

### 只编辑一个地图

- 选择包含地图目录的 View；
- 或填写地图为根文件并启用传递依赖；
- 深度 `0`，必要时按 `runtime` 标签过滤。

View 按路径筛选，依赖闭包按显式边筛选；两者同时使用时，最终内容受两组范围共同影响。

### CI 元数据任务

- 开启 Bare；
- 不选择 View、Layer 或依赖范围。

得到 Revision 树和仓库状态，但没有物化工作文件。

### 本机私有工具覆盖

- 正常 Clone；
- 填写初始 Layer 来源；
- 可选元数据键用于版本配对。

该组合不会传播到其他成员。

## 常见禁用原因

| 现象 | 原因 |
| --- | --- |
| **开始克隆**不可用 | 未选择父目录或目录名为空。 |
| View/Layer/依赖区域不可用 | 已开启 Bare。 |
| 直接文件 I/O 不可用 | 已开启 Bare。 |
| Layer 元数据键不可用 | Layer 仓库为空。 |
| 依赖标签和递归不可用 | 根文件为空。 |
| 深度不可用 | 未开启传递依赖，或根文件为空。 |
| Shared Store 不能关闭 | 设备设置已启用自动使用。 |
