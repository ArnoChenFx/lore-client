# 故障处理与安全边界

## 先看错误类别

Lore Client 会区分：

- 后端不可用；
- 版本不兼容；
- 权限不足；
- 离线或远端不可达；
- 仓库损坏；
- 路径或参数无效；
- 操作冲突或状态漂移。

不要把所有失败都解释为“仓库坏了”。先查看 Toast、字段旁错误和 **操作记录** 的结构化
详情。

## 升级后需要重新登录

Lore 0.9.0 起认证 Token 保存在新的 `tokenstore.toml` 中，旧的 `tokens.toml` 不会被
迁移，两代凭据互相独立。从旧版本升级后首次使用时，账户会显示未登录；对远端仓库
执行操作会触发系统浏览器认证，重新登录一次即可恢复。已登录账户无需重复此步骤。

## 无法打开目录

检查：

1. 选择路径是否存在且当前用户可访问；
2. 目录或其父级是否包含 `.lore`/旧格式元数据；
3. 是否误选了另一个 Lore 仓库内部的普通子目录；
4. 元数据是否存在但损坏。

存在损坏元数据时，软件不会提供原地初始化，以免覆盖现场。先备份目录，再使用验证或
外部恢复流程。

## 无法连接服务器

- 确认地址使用 `lore://主机:端口`；
- 服务器浏览地址只是临时值，仓库操作使用 **仓库工具 → 配置** 中保存的地址；
- 检查网络、VPN、防火墙和账户权限；
- 使用 **刷新** 重试目录；
- 若账户到期，可在恢复弹窗中选择 **重新认证**，也可进入 **仓库工具 → 账户** 登录。

已打开的远端仓库会按有上限的指数退避自动重试只读快照，并在通知流结束后重新订阅；
窗口重新回到前台或系统网络恢复时会立即探测一次。这些探测不会执行 Sync 或其他写操作。
若状态显示 **远端需要重新认证**，后台网络重试会停止并打开恢复弹窗。选择 **重新认证**
会刷新账户资料及该服务器下所有已打开仓库的真实状态；选择 **跳过并离线使用** 只在当前
会话暂停该服务器，不删除凭据或仓库绑定，本地工作仍可继续。之后显式登录或切换账户即可
重新验证并恢复联网，不需要重启应用。

浏览服务器成功不代表对每个仓库都有 Clone、Push 或 Link 目标权限。

## Clone 失败

常见原因：

- 父目录不可写；
- 本地目录名不是单级名称；
- 目标目录已存在且非空；
- Revision 短 ID 不唯一或 Branch 不存在；
- View 文件无效；
- Bare 与物化选项同时开启；
- 自动 Shared Store 开启但匹配 Store 缺失；
- Layer 来源或依赖参数无法解析。

失败后不要手工把半成品目录当成成功仓库。根据错误说明选择新的空目录或清理明确的
失败目标。

## 历史文件无法读取

Revision 存在不代表其所有 Fragment 已缓存在本地。检查：

- 当前是否离线；
- 仓库 remote URL 是否正确；
- 账户是否有该 Partition 权限；
- View 是否排除该路径；
- Shared Store 目录是否缺失；
- 内容是否已被本地 GC 回收但可以重新获取。

软件不会用工作区 Status 或演示文本冒充历史文件内容。

## Push 被拒绝

最常见原因是远端 Branch Latest 已变化：

1. 刷新并执行 Sync；
2. 检查产生的 Merge Revision 或冲突会话；
3. 解决所有冲突并创建收尾 Revision；
4. 再次 Push。

Push 失败前已上传的 Fragment 可能仍保留，重试时会复用；不能因此假定 Branch 指针已经
推进。

## 冲突操作受限

冲突会话中，普通 Stage、Unstage、Discard 与 Ignore 被禁用是预期行为。应使用当前冲突
类型的解决入口。未解决数归零后仍需创建收尾 Revision。

若需要放弃：

- **Restart** 丢弃当前解决进度并重新开始；
- **Abort** 尝试恢复操作前状态。

两者都会覆盖或恢复文件，确认前核对仓库和操作类型。

## View 无法应用

应用 View 需要：

- 工作区无本地更改；
- 无暂存内容；
- 无冲突；
- 当前 Revision 未在预览后漂移；
- 规则预览有效且仍与编辑内容一致。

重新刷新仓库状态、再次预览后再应用。不要把 `.loreignore` 当作 View 替代品。

## 外部工具无法启动

在 **客户端设置 → 集成** 检查：

- 工具是否显示“可用”；
- 可执行文件路径或 `PATH` 命令是否正确；
- Diff 是否同时包含 `{before}`、`{after}`；
- Merge 是否包含 `{base}`、`{local}`、`{remote}`、`{merged}`；
- 每个参数是否独占一行。

临时文件会在调用期间受控提供。外部程序自行保存或崩溃的行为由该程序负责。

## 协作锁没有阻止他人写入

这是当前设计边界：协作锁是提示型。它不会在所有提交、Push 或 Merge 路径强制拒绝写入。
把锁作为沟通信号，并结合 Branch 保护、评审和团队流程。

## 诊断与维护顺序

推荐顺序：

1. 普通刷新与操作记录；
2. **仓库工具 → 维护 → 开始验证**；
3. **高级诊断 → 只读验证**；
4. 仅对同一路径、确认报告后执行 **Heal**；
5. 必要时读取状态 Dump 或验证特定 Fragment；
6. GC 只用于回收未引用内容，不是通用修复。

**清理失效 Instance**、**运行 GC**、**Heal** 和 **Reset Branch Latest** 都可能造成不可逆
状态变化，执行前保留仓库备份或确认远端可重新获取内容。

## 0.x 预览版本

Lore 和 Lore Client 仍在 0.x 阶段。API、协议、磁盘格式和部分高级能力可能随固定版本
升级变化。手册以当前界面为准：

- 不承诺路线图功能已经稳定；
- 不把禁用按钮描述为可用；
- 重要流程先在测试仓库验证；
- 升级后重新检查 Clone、Sync、View、Layer/Link 和诊断行为。

## 获取有用的故障信息

先打开 **客户端设置 → 维护 → 打开日志目录**，找到 `lore-client.log`
和必要的最近轮转文件。先复现一次问题，再按时间戳找到对应命令的
`started` / `succeeded` / `failed` 记录。

报告问题时保留：

- Lore Client 版本；
- 操作名称和失败阶段；
- 错误类别与消息；
- 仓库是否在线、当前 Branch 与 Revision 短 ID；
- 是否使用 View、Layer、Link、Shared Store 或依赖选择；
- 可复现步骤。

应用会自动脱敏常见凭据模式，但日志仍可能包含本地路径和上游错误详情。
不要发送 Access Token、完整凭据、未检查的完整日志，或包含敏感目录的未脱敏状态 Dump。
