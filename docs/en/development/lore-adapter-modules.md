# Lore Adapter Modules

`src-tauri/src/lore_adapter.rs` is the stable adapter facade between the Tauri shell and the pinned Lore Rust API. The facade contains only shared state, event bridges, IPC DTOs, and structured errors. Commands and supporting implementation live under `src-tauri/src/lore_adapter/`.

## Command modules

| Module | Responsibility |
| --- | --- |
| `auth.rs` | Runtime information, authentication accounts, repository bindings, and authentication context refresh |
| `repository.rs` | Repository probing, initialization, publishing, cloning, status, shared stores, locks, dependencies, notifications, configuration entry points, and View entry points |
| `history.rs` | Revision history topology, metadata, details, lookup, amend, bisect, and restore |
| `branch.rs` | Branch queries, protection, diff, reset, and creation from an exact source |
| `composition.rs` | Tag, Layer, and Link commands |
| `maintenance.rs` | Verify, dump, Instance, remote information, and garbage collection |
| `workspace.rs` | Stage, workspace diff, Revision file reads, previews, file history, external tools, patches, and ignore rules |
| `operations.rs` | Commit, sync, push, checkout, cherry-pick, revert, merge, conflicts, archive, and workspace navigation |

These modules use `pub(crate)` so `lib.rs` can register both the functions and hidden macros generated by `#[tauri::command]`. Function names are unchanged, so the frontend IPC contract remains stable.

## Support modules

| Module | Responsibility |
| --- | --- |
| `tags.rs` | Tag metadata reads, writes, validation, and deduplication |
| `repository_lifecycle.rs` | Repository probing, initialization, publishing, cache release, and metadata directory resolution |
| `view.rs` | View rule parsing, preview, apply, dematerialization, and rollback |
| `configuration.rs` | Lossless configuration editing, value normalization, and commit identity resolution |
| `runtime.rs` | Async scheduling, heavy-read convergence, shared validation, shared-store parsing, and error mapping |
| `revision_storage.rs` | Revision Storage, Tree traversal, raw content reads, preview encoding, and structural diffing |
| `operation_support.rs` | Lore event capture, streaming summaries, conflict detection, and result wrapping |
| `external_tools.rs` | Path safety, external diff/merge, temporary files, patches, and ignore rules |

Support items default to `pub(super)` visibility for the `lore_adapter` parent. The parent connects sibling modules through private imports without exposing implementation details across the crate.

## Dependency rules

1. React continues to call IPC only through `src/services/lore.ts` and does not depend on the Rust module layout.
2. `src-tauri/src/lib.rs` registers commands only; Lore business logic does not belong there.
3. Cross-domain DTOs and structured errors remain in the facade; domain-only structures stay in their owning module.
4. Add a new command to an existing domain module and register it in `lib.rs`. Create a module only for a distinct, durable responsibility.
5. Keep support functions private. Use `pub(super)` only for genuine cross-domain reuse; do not widen visibility merely for tests.
6. `tests.rs` remains a child of the facade so it can cover private boundaries. Test names remain in English.

## Regression baseline

After changing the module layout, run at least `cargo test --manifest-path src-tauri/Cargo.toml`, `cargo fmt --manifest-path src-tauri/Cargo.toml -- --check`, `cargo check --manifest-path src-tauri/Cargo.toml`, `bun test`, and `bun run build`. When adding a Tauri command, also compare the implementation set with the `generate_handler!` registration set so an implemented command cannot remain unregistered.
